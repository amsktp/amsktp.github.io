# 프로젝트 1 : 비가시성 워터마크 연구

## ▪ 프로젝트 개요

**목적**

- 촬영·캡쳐 환경에서도 높은 검출률을 유지하는 **비가시성 워터마크 알고리즘 연구 및 실험 환경 구축**

**기간 / 규모**

- [지속 과제] / [1 ~ 2명]

**역할**

- 기존 프로토타입 기반 워터마크 알고리즘을 상용 수준으로 재설계
    - 비가시성 향상
    - 촬영 환경 검출 안정성 개선
    - 페이로드 복원율 개선
- 알고리즘 실험 환경 및 멀티 플랫폼 테스트 구조 설계·구현

---

## ▪ 문제 정의 (Problem)

- 기존 워터마크는 비가시성과 검출 안정성이 동시에 낮아 상용화에 한계
- 데스크톱 중심 구조로 모바일·웹 환경 검증이 어려움
- 팩스, 2Bit, CMYK 등 저비트·특수 포맷에서 삽입 자체가 불안정

---

## ▪ 접근 방식 (Approach)

- 워터마크 삽입 및 검출을 **공통 엔진 구조로 설계**하고 플랫폼별 입출력만 분리하는 방식 채택
- 모바일 환경에서의 기반 검출 실험을 위한 파라미터 조정 앱 개발
    - 카메라를 통한 프레임 내의 워터마크 검출
    - 이미지 검출 등
- 잉여 워터마크 영역을 활용한 추가 페이로드 삽입 구조 설계 (144bit × 3)
- 재현 가능한 실험 환경 구축
    - 암막 상자, 고정 조명, 디바이스 위치 고정 장치 활용

---

## ▪ 구현 내용 (Implementation)

- **멀티 플랫폼 테스트 프레임워크 구축**
    - Desktop: Windows / macOS / Linux (Docker)
    - Mobile: iOS / Android (카메라 프레임 기반 검출)
    - Web: 브라우저 환경에서 삽입·검출 테스트
- 비가시성, 인식률 개선
    - 주파수 필터를 사용하여 대상 영상에서 워터마크 성분 추출
    - 삽입 강도 조정 로직 개선
    - 디코딩 단계에서의 검출 방식 개선
    - 워터마크의 모양, 데이터를 삽입 할 색 채널, 삽입 방식 등.
        - RGB 기반 삽입의 한계를 분석 후 Lab 색 공간 기반 삽입 방식으로 전환
            - HVS 특성 고려
            - L / a / b 채널 실험 비교
- 확대 및 회전 여부를 판단하는 알고리즘을 개선하여 **검출 파이프라인 리소스 사용량 최적화**
- 팩스 및 2Bit 영상 환경에서도 적용 가능한 **저비트 영상용 워터마크 삽입 방식 개발**
- 워터마크 인식률 측정에 대한 객관적 지표 제작
    - 지표에 대해 저장하는 DB 및 백엔드, 해당 지표를 확인할 수 있는 웹 개발

---

## ▪ 성과 및 결과 (Result)

- 동일 조건 테스트 환경에서 기존 대비 검출 성공률 유의미하게 개선
- 기존에는 디버깅 가능한 환경이 Windows 뿐 이지만 iOS, Android, Web, Linux, MacOS, Windows 지원.
    - 추가로, Android, iOS, Windows 에 대해서 소스를 따로 관리했던 환경에서, 단일 소스로 각 프로젝트 별 차이를 제거.
- 불필요한 연산을 제거하여 **검출 알고리즘 리소스 사용량 감소**
- **특허 등록 2건**
    - 팩스/2Bit 영상 워터마크 삽입 방식
    - 비가시성을 강화한 영상 워터마크 삽입 방식
- 비가시성과 강인성(robustness) 간 Trade-off를 기준으로 삽입 강도 및 패턴 구조를 반복 실험하며 최적화
- 이후 비가시성 워터마크 기술이 **사내 주력 솔루션 (LabGuard) 의 핵심 기술로 확장**

# 프로젝트 2 : 비가시성 워터마크의 확장

## ▪ 프로젝트 개요

**목적**

- 비가시성 워터마크 기술을 활용하여 다양한 멀티미디어에 적용

**기간 / 규모**

- [지속 과제] / [1 ~ 2명]

**역할**

- 플랫폼 별 이미지, 비디오, PDF 등 다양한 멀티미디어에 워터마크 적용 검토

---

## ▪ 문제 정의 (Problem)

- 단순히 이미지 뿐 아니라 동영상, PDF 등 다양한 대상물에 워터마크를 적용하는 고객사의 니즈를 확인
- 이미지도 DPI, Color Profile 등 다양한 옵션 적용

---

## ▪ 접근 방식 (Approach)

- 고객사의 니즈에 따라 다양한 대상물에 비가시성 워터마크를 삽입과 검출 개발

---

## ▪ 구현 내용 (Implementation)

- 동영상
    - 두 가지 방식을 검토
        - FFMPEG 디코딩→프레임 삽입→재인코딩 방식 검토
        - **FFMPEG CLI를 사용해서, Filter 로 비가시성 워터마크 삽입 & 검출**
            - 코덱 다양성 및 메타데이터 보존 문제를 고려하여
            - **FFMPEG CLI Filter 기반 삽입 전략 채택**
- 이미지
    - magick++ 을 사용하여 CMYK 색 채널 지원과, DPI, 프로파일 등 옵션 적용
- PDF
    - 레스터화 방식 실험
        - 제거 난이도는 높으나
        - 용량 증가 및 품질 저하 발생
    - 레이어 기반 삽입 방식으로 전환
        - 용량 증가 최소화
        - 편집 제한 정책으로 보안 보완
    - 보안 강도 / 파일 용량 / 고객 사용성 간 Trade-off를 기준으로 해당 방식 선택
- 화면 (Windows)
    - MFC를 이용하여 화면에 워터마크를 삽입
- 출력물 (Windows)
    - DLL Injection을 통해, 프린트 함수를 후킹하여 인쇄 시 워터마크 삽입
- 팩스
    - 2Bit 이미지에 워터마크를 삽입

---

- 사내 주력 사업인 랩가드 솔루션으로 발전
- 사내 포토카드 사업으로 발전

---

## ▪ 내가 기여한 핵심 포인트 (My Contribution)

- 각 멀티미디어 대응

---

## **📌 “기술적 고민과 의사결정 사례”**

- PDF 레스터화 방식을 채택하지 않은 이유
    - 고객사들은 보안도 당연히 중요하지만 우선적으로 사용성에 문제가 없어야 하기 때문에, 용량을 늘리지 않는 것이 우선으로 판단했음.
- FFMPEG CLI Filter 방식을 선택한 이유
    - 동영상을 디코딩 → 인코딩까지 다 할 경우, 코덱의 다양함과, 메타데이터의 부재 등에 대한 처리 등 많은 고려가 필요하기 때문에 FFMPEG Cli Filter 전략을 선택함.

    - 기술 스택

    - 워터마크 검출 기능과, 하나의 이미지에 대한 간단한 편집 기능도 제공하여 검출이 좀 더 용이하게 만드는 기능을 포함
        - 현장 사용성을 고려하여 ROI 조정 및 로그 저장 기능 제공

# 프로젝트 6 : 랩가드 솔루션의 확장 3 - 랩가드 매니져

## ▪ 프로젝트 개요

**목적**

- 랩가드 솔루션의 관리웹을 만들어 휴먼에러를 최소화
- 소수 인원으로 랩가드 솔루션의 A to Z을 자동화

**기간 / 규모**

- 25년 12월 ~ 지속 과제

**역할**

- 웹 개발
- 백엔드 일부 개발

---

## ▪ 문제 정의 (Problem)

- 기존 플로우는 같은 팀 내 영업 담당자가 엑셀로 정리해놓은 문서를 참고해 타 팀의 백엔드 개발자에게 데이터 생성을 요청
- 백엔드 개발자가 데이터베이스에 들어가 해당 내용으로 데이터베이스에 직접 데이터를 추가
- 이 과정에서 누구든 휴먼에러가 발생할 수 있다고 판단

---

## ▪ 접근 방식 (Approach)

- 실제 사용자 입장에서 생각하고 1차 기획 및 개발
- 실제 사용자한테 Dev 환경에서 사용 테스트 요청 및 피드백 수령 후 2차 개발

---

## ▪ 구현 내용 (Implementation)

- 해당 프로젝트 설계 및 API 설계
- 웹 개발
- 일부 백엔드 개발
    - 해당 웹의 CRUD 및 라이센스

---

## ▪ 성과 및 결과 (Result)

- 실제 사용자와 데이터의 차이가 발생하지 않게 되어 솔루션 관리가 용이해 짐

---

## ▪ 내가 기여한 핵심 포인트 (My Contribution)

- 웹
- 백엔드
    - 해당 웹을 사용할 수 있는 계정에 대한 API 및 DB 구축
    - 라이센스 파일에 대한 API 및 DB 구축

---

    - Typescript
